2021 年那次为什么被删

commit 47e5a4d5 删掉动画时写的是 “Causing confusion during writing”。我用 Vue 2.6.12 和同样的模板做了最小复现。

操作实际播放动画的行
在第 2 行插入 NEW最后一行 c()，不是 NEW
只改第 1 行文字没有动画
解析抖动：少一行又回来最后一行 c() 再播一次

原因是 :key="index"：动画落在错误的元素上，还会被解析抖动反复触发。复现只跑了这个模板，没有重建 2020 年的完整应用。

动效规格

元素或事件写作时（方案 C）回放演示打断或例外
新 participant框 0–55%，生命线 35–100%，名字 45–100%。总长为笔画时长 D同样顺序，D = 520 ms新元素到达时，进行中的笔画直接到终态
新 message线 0–70%，箭头 62–82%，已有文字 55–100%同样顺序，D = 520 ms同帧有新 participant 时最多晚 0.3 D，整批不超过 250 ms
自己打出的文字每键直接出现，不做动画整段擦除式显现打字本身就是书写
已有元素移动110 ms 缓出，从当前位置继续同左连续按键不累积
删除90 ms 淡出，不倒放不适用只有用户真的删除时才出现
一次新增 5 个及以上每个 120 ms，错开，总长 240 ms不适用超过 120 个时直接显示
减少动态效果保留门控，不播动画不播跟随系统设置

D = clamp(1.6 × 按键间隔 EMA, 110, 240) ms，等待 = clamp(2.5 × EMA, 250, 500) ms，EMA 系数 0.3。这些是设计取值，还没有真人数据校准。

门控规则

门控只看前后两次文本的差异，不需要光标 API。它决定送给渲染器的文本，原文不变。

正在打的行送去渲染图上发生什么何时放行
Bo去掉这一行图不动打出分隔符、换行或停顿
re（关键字前缀）去掉这一行图不动关键字打完，或换行
Bob.原样箭头立刻开始画马上
Bob.getOr原样标签随键增长马上
Bob.getOrders(补 )标签不闪马上
Alice->Bo，已有 Bob去掉这一行不出现假 participant名字完全匹配，或打 :

其他任何情况，这一键会让已有元素消失沿用上一帧图不动下一键恢复，最多等 1200 ms

对照试验方案

  1. 8 到 12 人，用过 ZenUML 或 Mermaid。每人都用 A、B、C，顺序用拉丁方打乱，不告诉差异。
  2. 任务：抄写 3 份复杂度相近、约 15 行的 DSL，每份最多 3 分钟。全程录按键。
  3. 打字指标：WPM 和退格占比，用录制文件计算。
  4. 变化检测：随机遮住图，问“刚才新增了什么”，记准确率。
  5. 通过条件：C 相对 A 的 WPM 下降不超过 2%，错误率不上升，变化检测不低于 A。
  6. 样本小，只作方向判断。结果不明确时，上线前再用 feature flag 看关闭率和投诉。

这个原型还不能证明什么

  • 没有真人数据。所有速度和 WPM 都来自合成按键流。
  • 第一笔时间不含合成器和屏幕延迟，需要高速摄像才算端到端。
  • 原型基于 renderToSvg。ZenUml.render() 走 React 组件，并有等于上次渲染耗时、最长 2 秒的防抖（src/core.tsx:506）。上线要另做方案。
  • 编辑器内的直接操作（比如点按钮加 participant）没有打字问题，可能更适合先用动画。这里没有测。
  • 大图超出视口、滚动跟随、主题适配都只做了最低限度。
