## (a) Summary

**What was assessed.** The third-party repo https://github.com/Caho1/open-claude-ui ("v2") publishes a
reconstruction of Claude's design system: a storybook HTML page, `code-examples/cds-theme.css`, React
examples and Chinese analysis docs (`docs/v1`, `docs/v2`). The repo was read as data only. None of its
scripts were run and none of its code is copied into zenuml.

**Lineage.** The v2 storybook comes from the same source as the 2026-10-14 storybook site (`site.html`)
that produced D1-D12. It grew from 2533 to 4123 lines. So v2 is a later revision of the same
reconstruction, not an independent second source. Agreement between v1 and v2 is therefore not evidence.
Only the primary Claude CSS counts as evidence.

**Main findings.**

1. D1 (durations 60/120/200/300/450 ms) and D2 (three easing curves) are real `.cds-root` tokens in
   both WEB and ASAR. The v2 CSS dropped them; the real app still ships them.
2. The press feedback is not `active:scale-95`. Claude presses to `scale(.975)` over 60 ms ease-out and
   releases over 450 ms with a 15-point `linear()` spring (`--cds-btn-spring`). This changes P4.
3. Claude exits run at both 120 ms (`--cds-dur-snap`: `cds-pill-out` WEB 53701 / ASAR 5079, `epitaxy-band-exit`
   WEB 57942) and 150-180 ms (timeline status and block fades, SHARED 209, 276, 279). P2 keeps its 120 ms exit, now
   as the borrowed token `--zu-dur-snap`. Corrected 2026-10-20: an earlier draft claimed no exit used 120 ms.
4. Claude has 80 `prefers-reduced-motion: reduce` blocks and 16 `no-preference` blocks on web (96 total) and 13 `reduce` blocks on desktop, plus a
   `[data-reduce-motion]` override. The 2026-10-14 finding of "0" described the storybook, not Claude.
   This extends P3.
5. Most shadow, alpha-border and focus-ring values in the repo and in D4/D5 differ from the primary CSS.
   zenuml defines those values itself and records them as zenuml-owned.
6. Two runtime libraries (framer-motion, lucide-react) appear in the reconstruction. Neither is needed;
   see ADR 0003.

### Gate 1: token gate, `scripts/check-zu-tokens.mjs` (P1 onward)

Same idea as the reconstruction's `check-tokens.mjs` (every referenced token must be defined), written
fresh for zenuml. Spec:

- Input: the tokens file chosen in P1 (planned: `src/assets/tailwind.css`; pass it as `--tokens <path>`).
- Definitions: every match of `/(--zu-[a-z0-9-]+)\s*:/` in the tokens file.
- References: every match of `/var\(\s*(--zu-[a-z0-9-]+)/` and of Tailwind arbitrary values
  `/\[[^\]]*(--zu-[a-z0-9-]+)/` in `src/**/*.{ts,tsx,css,scss}`.
- Rule 1: every referenced token is defined. Print each missing token with `file:line`.
- Rule 2: every definition sits inside a `.zenuml` rule (or a `@media` / `@supports` block wrapping a
  `.zenuml` rule). A `:root` definition fails.
- Rule 3: every definition line carries a trailing comment that is either
  `/* src: <artifact file>:<line> */`, naming a file listed in `provenance.json`, or
  `/* zenuml-owned */` (ADR 0003). `<line>` refers to the prettified copy recorded in `provenance.json`
  under `prettified_copies` (SHA-256 and regeneration command: `npx -y prettier@3.9.10 --no-config --parser css --print-width 200 <original>`).
  A reviewer verifies by regenerating the copy and checking the hash, or by searching the artifact for the quoted text.
- Exit 0 when all rules pass, 1 otherwise. Run: `node scripts/check-zu-tokens.mjs --tokens src/assets/tailwind.css`.
  Add it to the cd.yml test job.

### Gate 7: bundle size budget (every PR)

```sh
bun run build:lib && gzip -9 -c dist/zenuml.esm.mjs | wc -c
```

Baseline: 450,152 bytes. Budget: 1% of the baseline for P0-P5 together.
450,152 × 0.01 = 4,501.52, rounded down to **4,500 bytes**. Ceiling: 450,152 + 4,500 = **454,652 bytes**
(gzip -9). The budget is cumulative: each PR records its own delta, and the sum may not pass 4,500.
Tokens, keyframes and a few `@media` blocks are text that compresses well, so 4.5 KB is generous for
CSS-only work. One motion library would spend the budget ten times over (framer-motion is 45,983 bytes,
10.2% of the baseline).
